## 9. Bugs found by hardware testing (all fixed + regression-tested)

| Symptom | Root cause | Fix |
| --- | --- | --- |
| Blank keys after USB flaps | missing-device writes bypassed retry queue | queue at boundary |
| Torn/stale frames | retries bypassed the write pump | retries via control lane |
| Stale pressed visuals | split-brain key caches | single owner |
| "Unmuted" after successful mute | PipeWire readback race | 150 ms settle |
| Shortcuts dead on KDE Wayland | wtype `-U` flag nonexistent + protocol rejected | uinput-first chain |
| Ctrl+V unrecordable | Electron default menu accelerators | `setIgnoreMenuShortcuts` while recording + capture-phase handlers |
| Labels/text layers wrong on hardware | icon half-size badges + label/layer split | full-canvas icon layers; titles import as labels |
| Fit modes "broken" | square test images (geometry) + preview hardcoded contain | verified 3-way pixel-distinct; preview fit-aware |
| Profile switch crashed app | stale dist + duplicate `undefined` IPC handler | honest failure + fresh builds |

## 11. Known limitations (honest)

- Discord **plugin** actions (mute-via-Discord, camera, screenshare, PTT
  toggle, notifications, audio device): require mac/win plugin binaries — no
  Linux version exists. System mutes (keys 0/1) cover the important cases.
- Wayland global-injection nuance: uinput events follow OS focus; Discord's
  X11 keybind grabs only intercept when an XWayland window is focused. System
  mutes are unaffected.
- Electron 28: fractional-scale *sizing* fixed via native Wayland; full
  crispness wants an Electron ≥30 bump.
- SD+ InfoBar rendering → device writes not wired yet (schema + renderer
  done); dial event model decompile queued.
- Icons whose WM_CLASS diverges from their desktop id need `StartupWMClass`
  in the entry (the Settings card shows the effective match pattern).
