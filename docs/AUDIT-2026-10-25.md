# BigDeck Audit — 2026-10-25

Scope: `src/main` device/action/plugin layers, cross-checked against Elgato
Stream Deck 7.6.0.23012 (macOS arm64) as reference implementation.
Purpose: explain "works sometimes / works here not there" hardware behavior
and set the refactor plan.

## Verdict

Core designs are sound (dual-lane write pump, diff-based HardwareSync,
layer compositor with LRU). The bugs live in component seams: two sources
of truth for key state, retry paths that bypass the write pump, polling
races, and an uninstantiated plugin system.

## Critical findings

### 1. Split-brain key-image caches
- `src/main/index.ts:53` module-level `keyImageCache` (written by IPC
  `DEVICE_SET_KEY_IMAGE`, read for press visuals on `key:down`)
- `src/main/actions/HardwareSync.ts` `keyImageCache` (written by profile
  render path)
Press visuals depend on which cache was updated last → stale/idle image
shown on press depending on write path. Random-seeming by design.

**Fix direction:** single owner of "what is on the key" (one KeyStateStore);
HardwareSync and IPC both go through it.

### 2. Device-flap failures are unrecoverable
`DeviceManager.setKeyImage` throws `Device not found` before the write
reaches `writeKeyImage`, so the failure never enters the `failedWrites`
retry queue. Renders scheduled during a flap are logged once and dropped
→ blank keys until manual profile re-apply.

**Fix direction:** retry-queue entries accepted at the DeviceManager
boundary (device-missing = retryable), not at write level.

### 3. Retry queue bypasses the write pump
`startRetryQueue` calls `deck.fillKeyBuffer` directly, interleaving raw
writes with animation-lane frames on the same device → torn/stale frames
while retries are in flight.

**Fix direction:** retries enqueue into the control lane like any other op.

### 4. Plugin system is a stub
`PluginManager.loadPluginFromDirectory` reads `manifest.json` metadata and
stops — plugins are never instantiated; `createPluginAPI` is dead code.
Only the `counter` built-in executes; OBS/Spotify/SystemMonitor are
decorative. User plugins cannot run at all.

**Fix direction (strategic):** implement the official Elgato `.sdPlugin`
host (WebSocket JSON protocol, plugin child-process spawn, property
inspector webview) — instant compatibility with the existing Elgato plugin
ecosystem. Reference: Elgato binary `ESDPluginManager`/`ESDPluginAdapter`
+ public SDK docs; protocol ops confirmed in binary strings
(`didReceiveSecrets`, `dialRotate`, etc.).

### 5. Hot-plug polling races
2 s `listStreamDecks()` polling + second re-lookup inside
`connectDevice`; no open-failure backoff → mid-enumeration opens,
connect/disconnect thrash on flaky USB.

**Fix direction:** event-driven hotplug (udev monitor / `udevadm monitor`
or usb-detection), single discovery source, connect backoff + hysteresis.

### 6. Magic timing
- 500 ms post-open sleep instead of readiness handshake (Elgato reads
  firmware/version with bounded retries before treating device as ready)
- 80 ms debounce on key-down only; key-up not debounced → press/release
  pairs can desync.

## What is already good
- `DeviceManager` dual-lane pump: control FIFO + latest-frame-wins
  animation lane, content-hash no-op writes, drift-free exact-time
  animation timers — right architecture.
- `HardwareSync` diff + per-key generation counters + trailing debounce.
- `KeyRenderer` layer compositor, frame cache with mtime-keyed cache
  entries, RGB strip for hardware.
- `ActionExecutor` covers keyboard/launch/multimedia/url/folder/script/
  macro/profile/page actions.

## Findings so far

### Device lifecycle (from onDeviceStatusChanged decompile)
- Device type is `esd::hw::device`; connect AND disconnect funnel through
  ONE handler with a bool.
- On connect they log `id, serial number, firmware version, bcdDevice` —
  i.e. the readiness handshake QUERIES the device (firmware+bcdDevice)
  before declaring it connected. No magic sleeps.
- On disconnect: notify observer lists, tear down per-device state, then
  `QTimer::start(2000)` — delayed re-enumeration timer.
- A "Stream Deck Dock" product ("2GBW99301") is special-cased in the same
  path.
- Settings persisted under a "Devices" key (QSettings-like).

### setImage pipeline (from sdkEventSetImageProcessor decompile)
1. Extract `"image"` field from plugin JSON command
2. Base64-decode
3. Write bytes to `$TMPDIR/StreamDeck/<UUID>` (CFUUIDCreate, hex-dashed)
4. Hand the FILE PATH to the render pipeline (transport/render decoupling;
   icon rendering happens outside the SDK client)

### Device I/O layer
- Statically linked **hidapi** (macOS backend: `hid_open_path`,
  `hid_read_timeout`, IOHIDDevice mach entries) — same core as BigDeck's
  node-hid. Error semantics: "hid_read_timeout: device disconnected".

### Action model class names (RTTI strings)
`MultiAction`, `DialStack`, `KeyStack`, `KeyAdaptor`, `KeyLogic`,
`KA_Custom` — plugin action object model.
